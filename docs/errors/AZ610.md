# AZ610: Not a development database

`rowstile push` (and `rowstile dev`, and the MCP server's `push`) changes a policy straight away, so it only changes a development database: one marked as one. The first push to a database that never had a policy marks it. This one has a policy and no mark (or had one: `rowstile remove` leaves it as it was, marked or not): if it is production, it takes migrations (`rowstile migrate`, then your migration tool); if it is a development database (say, one your migrations set up), mark it once with `rowstile push --development`.

Reported by the command, against a database.
